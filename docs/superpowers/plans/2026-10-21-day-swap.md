# 날짜 바꾸기 (같은 주 두 날짜의 코치 운동 교환) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 운동 페이지 주간 캘린더에서 길게 누르기로 같은 주 두 날짜의 코치 운동을 맞바꾼다. 같은 프로그램을 받는 선수 모두에게 반영된다.

**Architecture:** 교환은 두 날짜 코치 템플릿 행의 `date`와 `day_of_week`를 직접 맞바꾸는 것이다. 스키마 변경과 저장 상태는 없다. 판정 규칙은 DB를 모르는 순수 모듈에 두고 `node --test`로 검증한다. 서버 모듈이 DB를 읽고 써서 규칙을 적용하고, 화면은 `workout/page.tsx` 주간 스트립에 길게 누르기와 팝업을 붙인다.

**Tech Stack:** Next.js 16 App Router (route handlers), React 19, Supabase JS (service role, schema `ddodun`), Tailwind 4, `node --test` (Node 24, TS 직접 실행, `.ts` 확장자 상대 import)

**Spec:** `docs/superpowers/specs/2026-10-21-day-swap-design.md`

## Global Constraints

- 교환 대상은 요청한 선수에게 그 주 배정된 버전에 연결된 코치 템플릿(`extra_group_id IS NULL`)이다. `date`와 `day_of_week`를 함께 바꾼다.
- 두 날짜는 같은 주(`weekStartOf`, 월~일)에 있어야 하고, 둘 다 코치 운동이 있어야 한다.
- "기록 있음" = 그 날짜 그 날 코치 템플릿에 붙은 로그 중 내용이 있는 것. **모든 선수**를 센다. 내용 = `completed`, 공백 아닌 `result_value`·`memo`, `weight_unit` 외의 `sets_detail` 값.
- 마이그레이션은 없다. 에이전트가 DDL을 실행할 일이 없다.
- 실패 응답은 `HttpError(status, '<한국어 사유>')`로 보낸다. 상태 코드는 400(형식)과 409(규칙)이다.
- 화면 문구(확정): 팝업 제목 `"{요일} {일}과 바꿀 날"`, 팝업 하단 `"같은 프로그램을 받는 모두에게 바뀌어요"`, 토스트 `"{요일A} ⇄ {요일B} 바꿨어요"` + `되돌리기`.
- 사유 문구(확정): `'같은 날짜끼리는 바꿀 수 없어요'`, `'같은 주 안에서만 바꿀 수 있어요'`, `'운동이 없는 날은 바꿀 수 없어요'`, `'기록이 있는 날은 바꿀 수 없어요'`, `'이번 주 배정된 프로그램이 없어요'`

## Review Focus

1. **길게 누른 뒤 손을 떼면 click이 발생해 날짜가 이동한다.** 팝업을 연 그 click은 무시해야 하고, 짧은 탭은 지금처럼 날짜 이동만 해야 한다. → Task 3 수동 검증 1.
2. **교환 직후에도 화면이 옛 운동을 보여준다.** 두 날짜의 `dateCache`를 비우고 지금 날짜를 다시 불러와야 한다. 홈 화면도 다시 들어가면 새 값이어야 한다. → Task 3 수동 검증 3.
3. **두 번째 update가 실패해 두 날 운동이 한 날짜에 몰린다.** 보상 update로 원래대로 돌려야 한다. → Task 2 `swapDays` 구현 단계와 라이브 검증 4.
4. **다른 선수의 기록이 있는 날이 바뀌어 그 선수 기록이 사라진다.** 기록 판정이 요청자만 보면 안 된다. → Task 2 라이브 검증 2(다른 선수 로그로 거부 확인).
5. **`sets_detail`에 단위만 있는 행 때문에 날이 잠긴다.** → Task 1 `hasContent` 테스트.

```ts
const L = (p: Partial<LogLike>): LogLike => ({ date: '2026-10-21', template_id: 't-wed', is_custom: false, completed: false, result_value: null, memo: null, sets_detail: null, ...p })

test('hasContent: 빈 행·단위만·공백 메모는 false', () => {
  assert.equal(hasContent(L({})), false)
  assert.equal(hasContent(L({ sets_detail: { weight_unit: 'lb' } })), false)
  assert.equal(hasContent(L({ sets_detail: {} })), false)
  assert.equal(hasContent(L({ sets_detail: '{}' })), false)
  assert.equal(hasContent(L({ memo: '  ' })), false)
})
test('hasContent: 완료·결과·메모·무게는 true', () => {
  assert.equal(hasContent(L({ completed: true })), true)
  assert.equal(hasContent(L({ result_value: '12:30' })), true)
  assert.equal(hasContent(L({ memo: '좋았음' })), true)
  assert.equal(hasContent(L({ sets_detail: { weight: 135, weight_unit: 'lb' } })), true)
  assert.equal(hasContent(L({ sets_detail: '{"weight":95}' })), true)
})
test('computeRecordDates는 그 날 코치 템플릿에 붙은 내용 있는 로그만', () => {
  const ids = new Map([['2026-10-21', new Set(['t-wed'])], ['2026-10-22', new Set(['t-thu'])]])
  assert.deepEqual([...computeRecordDates([L({ completed: true })], ids)], ['2026-10-21'])
  assert.deepEqual([...computeRecordDates([L({})], ids)], [])                                    // 빈 행
  assert.deepEqual([...computeRecordDates([L({ completed: true, template_id: 't-thu' })], ids)], []) // 다른 날 템플릿
  assert.deepEqual([...computeRecordDates([L({ completed: true, is_custom: true, template_id: null })], ids)], [])
})
test('checkSwap 규칙과 순서', () => {
  const ctx = { coachDates: new Set(['2026-10-19', '2026-10-21', '2026-10-22', '2026-10-27']), recordDates: new Set(['2026-10-19']) }
  assert.equal(checkSwap('2026-10-21', '2026-10-21', ctx), '같은 날짜끼리는 바꿀 수 없어요')
  assert.equal(checkSwap('2026-10-22', '2026-10-27', ctx), '같은 주 안에서만 바꿀 수 있어요')
  assert.equal(checkSwap('2026-10-21', '2026-10-24', ctx), '운동이 없는 날은 바꿀 수 없어요')
  assert.equal(checkSwap('2026-10-19', '2026-10-21', ctx), '기록이 있는 날은 바꿀 수 없어요')
  assert.equal(checkSwap('2026-10-22', '2026-10-21', ctx), null)
})
```
