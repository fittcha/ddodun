# 날짜 바꾸기 (본인 일정 요일 교환) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 선수가 운동 페이지 주간 캘린더에서 같은 주 두 날짜의 코치 운동을 본인 일정에서만 맞바꾸고 되돌릴 수 있게 한다.

**Architecture:** 새 테이블 `ddodun.day_swaps`에 (선수, date_a, date_b)를 저장한다. 서버의 `resolveTemplates`가 짝 날짜의 템플릿을 대신 돌려주므로 코치 원본과 로그 구조는 그대로다. 판정 규칙(같은 주인지, 기록이 있는지 등)은 DB를 모르는 순수 모듈에 두고 `node --test`로 검증한다. 화면은 `workout/page.tsx` 주간 스트립에 길게 누르기와 팝업을 붙인다.

**Tech Stack:** Next.js 16 App Router (route handlers), React 19, Supabase JS (service role, schema `ddodun`), Tailwind 4, `node --test` (TS 직접 실행, `.ts` 확장자 import)

**Spec:** `docs/superpowers/specs/2026-10-21-day-swap-design.md`

## Global Constraints

- 교환은 **본인에게만** 적용한다. 코치 원본 `workout_templates`, 다른 선수의 응답은 절대 바뀌지 않는다.
- 두 날짜는 같은 주(`weekStartOf` 기준, 월~일)에 있어야 한다. 한 날짜는 동시에 하나의 교환에만 속한다.
- 개인 추가운동(`extra_group_id` 있음)은 교환되지 않는다. `resolveExtras`는 수정 금지.
- "기록 있음" = 그 날짜에 **지금 보이는 코치 템플릿**에 붙은 로그 중 내용이 있는 것(`completed`, `result_value`, `memo`, `sets_detail` 값). 빈 행, 커스텀 기록, 추가운동 기록은 세지 않는다(spec §5).
- 마이그레이션은 사용자가 Supabase SQL Editor에서 직접 실행한다. 에이전트는 DDL을 실행할 수 없다. Task 2의 라이브 검증은 사용자가 실행한 뒤에만 가능하다.
- 서버 실패 응답은 `HttpError(status, '<한국어 사유>')`를 써서 `{ error }`로 보낸다. 상태 코드는 400(형식 오류)과 409(규칙 위반)이다.
- 화면 문구(확정): 팝업 제목 `"{요일} {일}과 바꿀 날"`, 토스트 `"{요일A} ⇄ {요일B} 바꿨어요"` + `되돌리기`, 카드 위 줄 `"⇄ {요일}({일}) 운동을 하는 날 · 원래대로"`, 되돌리기 메뉴 `"↺ 원래대로"`.

## Review Focus

1. **길게 누른 뒤 손을 떼면 click이 발생해 날짜가 이동한다.** 길게 누르기로 팝업이 열렸다면 그 click은 무시해야 한다. 짧은 탭은 지금처럼 날짜 이동만 한다. → Task 3 수동 검증 항목.
2. **교환 직후에도 화면이 옛 운동을 보여준다.** `dateCache`(page 모듈)에 두 날짜의 옛 결과가 남아 있다. 교환과 되돌리기 직후 두 날짜 캐시를 비우고 다시 불러와야 한다. → Task 3.
3. **교환 상태에서 적은 기록이 되돌리기 후 사라진다.** 되돌리기 판정은 "지금 보이는 템플릿(교환 반영)" 기준으로 기록을 세야 한다. 원래 템플릿 기준으로 세면 막아야 할 되돌리기가 통과된다. → Task 1 `computeRecordDates` 테스트 + Task 2 라이브 검증.
4. **`sets_detail`에 단위만 들어간 행이 "기록"으로 잡혀 날이 잠긴다.** `weight_unit`만 있는 객체는 빈 것으로 본다. → Task 1 `hasContent` 테스트.
5. **팝업이 월요일·일요일 끝에서 화면 밖으로 나간다.** 첫 칸과 마지막 칸은 정렬을 보정한다. → Task 3 수동 검증.

### Task 1: 마이그레이션 SQL + 순수 규칙 모듈

**Interfaces:**
- Produces (`day-swap-rules.ts`):
  - `export interface DaySwap { id: string; date_a: string; date_b: string }`
  - `export interface LogLike { date: string; template_id: string | null; is_custom: boolean; completed: boolean; result_value: string | null; memo: string | null; sets_detail: unknown }`
  - `normalizePair(a: string, b: string): { date_a: string; date_b: string }` — 작은 날짜가 `date_a`
  - `swapOf(swaps: DaySwap[], date: string): DaySwap | null`
  - `partnerOf(swaps: DaySwap[], date: string): string | null`
  - `hasContent(log: LogLike): boolean`
  - `computeRecordDates(logs: LogLike[], templateIdsByDate: Map<string, Set<string>>, swaps: DaySwap[]): Set<string>` — `templateIdsByDate`는 **원래 날짜**별 코치 템플릿 id. 날짜 D에서 보이는 id 집합은 `templateIdsByDate.get(partnerOf(swaps, D) ?? D)`이다. 로그가 `!is_custom && template_id ∈ 그 집합 && hasContent`이면 D는 기록 있음.
  - `checkCreate(a: string, b: string, ctx: { coachDates: Set<string>; recordDates: Set<string>; swaps: DaySwap[] }): string | null` — 위반 시 한국어 사유, 통과 시 null
  - `checkUndo(swap: DaySwap, recordDates: Set<string>): string | null`
  - 사유 문구(확정, 검사 순서대로): `'같은 날짜끼리는 바꿀 수 없어요'`, `'같은 주 안에서만 바꿀 수 있어요'`, `'운동이 없는 날은 바꿀 수 없어요'`, `'이미 다른 날과 바뀐 날이에요'`, `'기록이 있는 날은 바꿀 수 없어요'`; undo는 `'기록이 있어 되돌릴 수 없어요'`

```ts
const S = (id: string, a: string, b: string): DaySwap => ({ id, date_a: a, date_b: b })
const L = (p: Partial<LogLike>): LogLike => ({ date: '2026-10-21', template_id: 't-thu', is_custom: false, completed: false, result_value: null, memo: null, sets_detail: null, ...p })

test('normalizePair는 작은 날짜를 date_a로', () => {
  assert.deepEqual(normalizePair('2026-10-22', '2026-10-21'), { date_a: '2026-10-21', date_b: '2026-10-22' })
})
test('partnerOf는 양방향', () => {
  const s = [S('1', '2026-10-21', '2026-10-22')]
  assert.equal(partnerOf(s, '2026-10-21'), '2026-10-22')
  assert.equal(partnerOf(s, '2026-10-22'), '2026-10-21')
  assert.equal(partnerOf(s, '2026-10-23'), null)
})
test('hasContent: 빈 행·단위만 있는 행은 false', () => {
  assert.equal(hasContent(L({})), false)
  assert.equal(hasContent(L({ sets_detail: { weight_unit: 'lb' } })), false)
  assert.equal(hasContent(L({ sets_detail: {} })), false)
  assert.equal(hasContent(L({ memo: '  ' })), false)
})
test('hasContent: 완료·결과·메모·무게는 true', () => {
  assert.equal(hasContent(L({ completed: true })), true)
  assert.equal(hasContent(L({ result_value: '12:30' })), true)
  assert.equal(hasContent(L({ memo: '좋았음' })), true)
  assert.equal(hasContent(L({ sets_detail: { weight: 135, weight_unit: 'lb' } })), true)
  assert.equal(hasContent(L({ sets_detail: '{"weight":95}' })), true) // 문자열 JSON도 파싱
})
test('computeRecordDates는 교환 반영 템플릿 기준', () => {
  const ids = new Map([['2026-10-21', new Set(['t-wed'])], ['2026-10-22', new Set(['t-thu'])]])
  const swaps = [S('1', '2026-10-21', '2026-10-22')]
  // 수요일에 목요일 템플릿으로 적은 기록 → 교환 상태에서 수요일은 기록 있음
  assert.deepEqual([...computeRecordDates([L({ completed: true })], ids, swaps)], ['2026-10-21'])
  // 교환이 없으면 같은 로그는 수요일에 보이지 않으므로 기록 아님
  assert.deepEqual([...computeRecordDates([L({ completed: true })], ids, [])], [])
  // 커스텀 기록은 세지 않음
  assert.deepEqual([...computeRecordDates([L({ completed: true, is_custom: true, template_id: null })], ids, swaps)], [])
})
test('checkCreate 규칙과 순서', () => {
  const ctx = { coachDates: new Set(['2026-10-19', '2026-10-21', '2026-10-22', '2026-10-27']), recordDates: new Set(['2026-10-19']), swaps: [S('1', '2026-10-20', '2026-10-23')] }
  assert.equal(checkCreate('2026-10-21', '2026-10-21', ctx), '같은 날짜끼리는 바꿀 수 없어요')
  assert.equal(checkCreate('2026-10-22', '2026-10-27', ctx), '같은 주 안에서만 바꿀 수 있어요')
  assert.equal(checkCreate('2026-10-21', '2026-10-24', ctx), '운동이 없는 날은 바꿀 수 없어요')
  assert.equal(checkCreate('2026-10-21', '2026-10-23', { ...ctx, coachDates: new Set([...ctx.coachDates, '2026-10-23']) }), '이미 다른 날과 바뀐 날이에요')
  assert.equal(checkCreate('2026-10-19', '2026-10-21', ctx), '기록이 있는 날은 바꿀 수 없어요')
  assert.equal(checkCreate('2026-10-22', '2026-10-21', ctx), null)
})
test('checkUndo', () => {
  const s = S('1', '2026-10-21', '2026-10-22')
  assert.equal(checkUndo(s, new Set(['2026-10-22'])), '기록이 있어 되돌릴 수 없어요')
  assert.equal(checkUndo(s, new Set()), null)
})
```
