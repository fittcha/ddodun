# 날짜 바꾸기 (본인 일정만 요일 교환) 설계

- **날짜**: 2026-10-21
- **대상 앱**: DDODUN (`/Users/chacha/lab/ddodun/app`)

## 1. 왜

목요일마다 하는 EMOM이 수요일로 당겨지는 일이 자주 있다. 지금은 그럴 때마다 DB를 직접 고쳐 수↔목 운동을 바꾼다. 선수가 **앱에서 직접 두 날짜의 코치 운동을 통째로 맞바꿀 수 있어야** 한다.

- 바뀌는 건 **그 선수 본인의 일정뿐**이다. 코치 원본(`workout_templates`)과 같은 프로그램을 받는 다른 선수의 화면은 그대로다.
- 그룹 단위 복제(「이 날짜에 복제」)는 이번 범위가 아니다. 지금 동작 그대로 둔다(사용자 결정).

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 운동 페이지 상단 주간 캘린더에서 날짜를 꾹 누르면, 같은 주 다른 요일과 그 날의 코치 운동을 맞바꾼다.
- 언제든 원래대로 되돌릴 수 있다.

**비목표**
- 코치 프로그램 자체 수정, 다른 선수에게 반영
- 주를 넘는 교환(다른 주 날짜와 바꾸기)
- 운동 없는 날로 "옮기기"(한쪽이 빈 날)
- 개인 추가운동(extra) 이동 — 추가운동은 원래 날짜에 그대로 남는다
- 그룹 복제 변경

**실패로 보는 것 (기능이 돌아가도)**
- 이미 적어둔 기록이 화면에서 사라진 것처럼 보이는 것
- 다른 선수나 코치 원본이 바뀌는 것
- 평소 날짜 탭(날짜 이동) 동작이 달라지거나 헷갈려지는 것

## 3. 사용자가 보는 것 (사용자와 확정)

목업: `.superpowers/brainstorm/30933-1792543506/content/week-strip-swap-v2.html` 의 **방식 2**.

1. **진입**: `src/app/workout/page.tsx` 주간 스트립에서 요일 버튼을 **길게 누르면**, 그 요일 바로 아래에 작은 팝업이 뜬다. 짧게 탭하면 지금처럼 날짜 이동만 한다.
2. **팝업 (교환 전)**: 제목 "수 21과 바꿀 날", 아래에 **같은 주의 다른 요일 칩**. 칩 하나를 탭하면 즉시 교환된다. 확인 단계는 없다.
   - 고를 수 없는 칩은 흐리게 표시하고 탭이 안 된다. 대상: 코치 운동이 없는 날, 기록이 있는 날(§5 정의), 이미 다른 날과 바뀌어 있는 날.
   - 꾹 누른 날 자신이 위 조건(운동 없음, 기록 있음)에 걸리면, 팝업에 칩 대신 이유 한 줄을 보여준다.
3. **교환 직후**: 토스트 "수 ⇄ 목 바꿨어요 · 되돌리기". 되돌리기를 누르면 교환이 취소된다.
4. **교환 상태 표시**: 바뀐 두 요일 버튼 오른쪽 위에 작은 ⇄ 배지를 단다. 그 날 운동 카드 위에는 "⇄ 목(22) 운동을 하는 날 · 원래대로" 한 줄을 넣는다.
5. **되돌리기**: 바뀐 날을 다시 길게 누르면 같은 팝업에 「↺ 원래대로」 하나만 나온다. 위 4의 "원래대로" 링크도 같은 동작이다.

## 4. 동작 규칙

- 교환은 **(선수, 날짜 A, 날짜 B)** 한 쌍이다. A와 B는 같은 주(월~일, `weekStartOf` 기준)에 있어야 한다.
- 한 날짜는 동시에 하나의 교환에만 속할 수 있다. 연쇄·3자 교환은 없다.
- 교환 중일 때 날짜 A를 열면 **B의 코치 운동**이 보이고, B를 열면 A의 운동이 보인다. 홈 화면의 "오늘 운동"도 같은 API를 쓰므로 똑같이 따라간다.
- **기록은 실제로 운동한(보고 있는) 날짜로 저장된다.** 지금도 `WorkoutSection`은 로그를 페이지 `date`로 저장하고(`WorkoutSection.tsx:391`), 로그는 `template_id`로 카드에 붙는다. 그래서 수요일에 목요일 템플릿으로 적은 기록은 `(user, 수, 목-템플릿 id)`로 저장되고, 기존 유니크 인덱스 `(user_id, date, template_id)`와도 충돌하지 않는다.
- 기록이 있는 날은 교환할 수 없다(§3-2). 그래서 교환이나 되돌리기 때문에 기존 기록이 숨겨지는 일은 생기지 않는다.
  - 단, **교환한 뒤 기록을 적고 나서 되돌리기**를 하면, 그 기록은 지금 그 날에 보이는 템플릿과 맞지 않아 화면에서 사라진다. 그래서 **교환된 두 날 중 하나에라도 기록이 있으면 되돌리기도 막고**, 팝업에 "기록이 있어 되돌릴 수 없어요"를 보여준다.
- 캘린더 점(운동 있는 날 표시): 교환은 운동 있는 두 날끼리만 하므로 날짜 집합이 바뀌지 않는다. `resolveTemplateDates`는 수정하지 않는다.

## 5. 데이터 / 서버

**새 테이블** (마이그레이션은 사용자가 Supabase SQL Editor에서 직접 실행한다. 파일은 `docs/sql/migration-day-swaps.sql`):

```sql
CREATE TABLE ddodun.day_swaps (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  athlete_id  uuid NOT NULL REFERENCES ddodun.users(id) ON DELETE CASCADE,
  date_a      date NOT NULL,
  date_b      date NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now(),
  CHECK (date_a < date_b)
);
CREATE UNIQUE INDEX day_swaps_athlete_a ON ddodun.day_swaps (athlete_id, date_a);
CREATE UNIQUE INDEX day_swaps_athlete_b ON ddodun.day_swaps (athlete_id, date_b);
```

`date_a < date_b`로 정규화해 저장한다. "한 날짜는 한 교환에만"은 A/B 교차까지 막아야 하므로 서버에서 확인한다. 유니크 인덱스는 같은 칸끼리의 중복만 막는다.

**조회 변경**: `src/lib/server/programs.ts`의 `resolveTemplates(athleteId, date)` 맨 앞에서 그 선수의 교환을 찾는다. `date`가 어떤 교환의 A나 B이면 짝 날짜로 바꿔서 기존 로직을 실행한다. `assignedVersionId`의 주 계산도 짝 날짜로 하지만, 같은 주라 결과는 같다.

- 응답에 `swappedWith: string | null`을 추가한다. `/api/workouts/[date]` 응답이 `{ templates, extras, swappedWith }`가 된다. 화면이 §3-4 줄과 배지를 그리는 데 쓴다.
- `resolveExtras`는 바꾸지 않는다. 추가운동은 원래 날짜에 남는다.

**API** (모두 `requireUser`, 본인 것만):
- `GET /api/day-swaps?start=&end=` → 그 주의 교환 목록. 주간 스트립의 ⇄ 배지와 팝업 칩 활성 여부에 쓴다.
- `POST /api/day-swaps { dateA, dateB }` → 교환을 만든다. 서버 검증: 같은 주인지, 둘 다 코치 운동이 있는지, 둘 다 기록이 없는지, 둘 다 다른 교환에 속하지 않는지. 실패하면 400/409와 한국어 사유를 돌려준다.
- `DELETE /api/day-swaps/[id]` → 되돌리기. 서버 검증: 두 날 모두 기록이 없을 것.

**팝업 칩 활성 판단에 필요한 데이터**: `weekTemplateDates`(`resolveTemplateDates`)에는 개인 추가운동만 있는 날짜도 섞여 있어서 칩 판단에 쓸 수 없다. 그래서 day-swaps GET이 그 주의 **코치 운동 있는 날**, **기록 있는 날**, **교환 목록**을 함께 돌려준다 *(빌더 체크 후 수정, 내 판단)*.

**"기록 있음"의 정의 (사용자 확정)** — 이 문서의 칩 비활성(§3-2), 되돌리기 차단(§4), POST·DELETE 검증, GET 응답은 모두 이 정의 하나를 쓴다:
- 그 선수의 `workout_logs` 중 `date = D`이고, `template_id`가 **지금 D에 보이는 코치 템플릿**(교환 중이면 짝 날짜의 템플릿, 즉 `resolveTemplates(athlete, D)` 결과)에 속하는 행
- 그중 **내용이 있는 행**만 센다: `completed = true`, 또는 `sets_detail`이 비어 있지 않음, 또는 `result_value`나 `memo`가 비어 있지 않음
- 세지 않는 것: 체크했다가 해제해 남은 빈 행, 커스텀 기록(`is_custom`, `template_id` 없음), 추가운동 기록. 이것들은 교환해도 화면에서 사라지지 않는다.
- 이유: 체크 해제해도 빈 행이 남고 앱에 지우는 화면이 없다. 행 존재만으로 막으면 실수 한 번에 그 날이 영구히 잠긴다.

## 6. 화면 (클라이언트)

- `src/app/workout/page.tsx` 주간 스트립 버튼에 길게 누르기를 붙인다(포인터 이벤트로 ~500ms, 그 사이 움직이면 취소). 길게 누른 뒤에는 click이 날짜 이동으로 처리되지 않게 막는다.
- 팝업은 요일 버튼 아래에 붙인다. 바깥을 탭하면 닫힌다. 화면 밖으로 나가지 않도록 위치를 보정한다(예: 월요일은 왼쪽 정렬).
- 교환하거나 되돌린 뒤에는 두 날짜의 `dateCache`와 `workout-templates.ts`의 `inflight` 캐시를 비우고, 지금 보는 날짜를 다시 불러온다.
- 홈(`src/app/page.tsx`)의 오늘 운동은 같은 API를 쓰므로 따로 손볼 것이 없다.

## 8. 검증

테스트 프레임워크가 없다. `npx tsc --noEmit`과 `npm run build`를 돌리고, 일회용 node 스크립트로 실제 DB를 왕복 확인한다.
1. 교환 생성 → 두 날짜 `/api/workouts/[date]` 응답이 서로 바뀌었는지 확인
2. 같은 프로그램을 받는 다른 선수의 응답은 그대로인지 확인
3. 기록이 있는 날 교환, 다른 주 교환, 이미 교환된 날 교환 → 모두 거부되는지 확인
4. 빈 기록 행(체크 해제 후 남은 것)이나 커스텀 기록만 있는 날 → 교환이 허용되는지 확인
5. 되돌리기 → 원상 복구되는지 확인

테스트용 교환 행은 끝나면 지운다.
